HASHOS / IMPLEMENTATION

How it works

01 / GUIDED RECOVERY

Plan before execution

Confirm a hash mode, add context words or a known pattern, set a time budget, and review staged attacks before starting. Ambiguous hashes require user confirmation.

02 / COMPUTE

Validate the hardware

Packaged AMD, Intel, and NVIDIA paths are checked with per-device known answers. Hashcat uses a verified device; John provides a CPU route when GPU compute is unavailable.

03 / OPERATIONS

Control and review jobs

Queue, pause, resume, and stop jobs from the browser workspace. Results can be exported, with one compute job running at a time.

04 / STATE

Persistence is explicit

Application state is volatile by default. An existing LUKS/ext4 volume can be attached for encrypted credentials, uploads, history, and results; no disk is selected or formatted automatically.

HASHOS / RELEASE STATE

Availability & limits

Release

The v0.8 x86_64 image ↗ is public. The release notes document BIOS and UEFI QEMU boot checks, guided workflows, HTTPS pairing, and CPU fallback. Physical USB testing of this release remains outstanding.

Source

The GitHub repository ↗ now contains the application source, build scripts, tests, and documentation. The source includes an Intel driver recovery improvement added after the v0.8 ISO was built.

Download

Download all three ISO parts and both checksum files from the v0.8 release ↗. Keep them together and run bash scripts/assemble-iso-parts.sh ↗ to verify the parts and assemble the 5.52 GB ISO. The release notes include full instructions.

Hardware

GPU readiness is validated per device; compatibility is not guaranteed for every card or hash mode. Physical NVIDIA and Intel GPU testing remains outstanding.

Use only hashes and challenges you are authorized to audit.
